# 個人設定の移行と復旧（WIP）

この手順は公式OSを別コピーで軽量化し、各機体の個人情報を選択して移すための一般的な作業メモ。自動化済みの手順ではない。[OS軽量化の概要](README.md)と[実機検証](validation.md)も参照。

## バックアップと取り扱い

1. 移行元のSDを全域バックアップする。SDと保存先の物理ディスク、容量、識別子を確認して読み取り専用で取得し、バックアップ全体の再読込ハッシュを記録する。ドライブレターやディスク番号は抜き差しで変わる。
2. 写真・文書・個人辞書・アプリ設定など、その機体にしかない必要なデータを選択して控える。パッケージや再ダウンロードできる実行ファイルの一覧は、個人データとは別に扱い、用途と依存を確認して再導入する。
3. OS画像・完全バックアップ・個人データのアーカイブは秘密情報を含みうる。実際のファイル、パスワードハッシュ、秘密鍵、認証トークン、ユーザー名、端末名、個人ネットワークの情報を公開リポジトリやログに掲載しない。保管場所、対象機、時点、ハッシュは各自の非公開記録で管理する。
4. 同一PC上だけでなく別媒体にも控えを取り、復旧できることを確認する。作成後の実機の変更は古いイメージに含まれない。

## 何を移すか

| 分類 | 確認するもの |
|---|---|
| ユーザー | アカウントのUID/GID、所属グループ、ホーム、シェル、ログイン方法。所有者・権限・シンボリックリンクも維持する |
| 個人データ | 文書、個人プロジェクト、個人辞書、入力設定、アプリ固有設定。不要なキャッシュと分ける |
| 接続 | Wi-Fiプロファイル、Bluetoothペアリング、SSH公開鍵、VPN設定。秘密を含むファイルは機体別に保管 |
| 機体の同一性 | SSHホスト鍵、VPNの認証状態、machine-id、hostname。別機体からそのまま複製しない |
| 起動 | 初回設定完了の状態、systemd userサービスのlinger、ランチャー、無線のrfkill、タイムゾーン |

同じ機体の復旧か、新しい機体への移行かを区別する。既存認証状態のコピーを複数の稼働機で共有すると識別が衝突するため、新しい機体では固有のID生成と認証を行う。SSHのホスト鍵が変わった場合は、検証済みの鍵を確認してから接続先の登録を更新する。

## 作業の順序

1. 公式イメージの作業コピーに必要なパッケージとアプリを導入し、削除候補はAPTのシミュレーションで確認する。更新時は署名検証を維持し、依存関係とinitramfsを検証する。
2. 移行元から機体固有の情報を必要な範囲で取得し、対象機を確認して作業コピーに適用する。丸ごとのホーム復元が必要かは個別に判断する。前の機体のホーム・認証状態を削除して別機体用に作り直す操作は、対象画像を間違えるとデータが失われるためコピー上でのみ行う。
3. 登録ユーザーとグループ、アクセス権、パッケージ整合性、初回設定状態を確認する。一般ユーザーで使うアプリはそのユーザーでも試す。
4. 画像の整合性と長さを確認してから対象SDへ書き込み、画像の全範囲を読み戻してハッシュを照合する。起動後はパーティションが拡張されるため、SD全体のハッシュが書き込み直後と変わるのは正常。
5. 内蔵画面、入力、ADB、無線、SSH、アプリ、カメラ、HDMI、Bluetoothを利用目的に応じて実機で確認する。GUI日本語入力は必要な入力モジュールが残っているか個別に確認する。

このリポジトリには機体ごとのバックアップ場所や認証情報は含めない。特定環境の一時スクリプトは画像パス・パーティションoffset・物理ディスク番号が固定されていることがあり、別環境にそのまま適用しない。
